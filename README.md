Домашние задания выполняются в смешанной среде VSCode + терминал, операционная система Ubuntu 24.04. 
Версия компилятора g++ (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0
Версия Cmake: 3.28.3
 
Организация репозитория: каждое домашнее задание (кроме самого первого) находится в своей папке. Сдача домашнего задания производится в рамках ветки. Все корректировки в процессе приемки задания коммитятся  текущую ветку ДЗ, после принятия предподавателем ДЗ ветка мержится в мастер. Таким образом в мастере находится все сданные домашние задания по курсу. В отдельных ветках находятся домашние задания, которые еще не сданы.

Файл .gitignore также помимо разных вспомагательных исключений содержит паки с материалами урока, которые выкладываются преподавателем.

Непрерывная интеграция (.github/workflows/release.yml): workflow запускается при пуше в ветки master, feature/github_actions и в любую ветку домашнего задания (шаблон hw*). При пуше в ветку ДЗ выполняется полный цикл — конфигурирование, сборка, тесты, упаковка .deb — только для проекта этой ветки, то есть папки hw-lesson{N}; номер занятия извлекается из имени ветки. Релиз при этом не создаётся, пуш в ветку ДЗ служит проверкой сборки.

При пуше в мастер (а также в feature/github_actions) workflow по git diff между предыдущим и текущим коммитом пуша определяет затронутые этим пушем папки hw-lesson{N} — то есть мерж принятого ДЗ — и собирает их. Если ни одна папка ДЗ не затронута, собирается корневой проект (первое ДЗ). GitHub Release с тегом, равным номеру запуска, создаётся только при пуше в мастер; ассетами релиза становятся все собранные .deb пакеты.

Технические детали: каждый проект конфигурируется и собирается out-of-source в собственной папке build с -DPATCH_VERSION=<номер запуска>; тесты выполняются через ctest, который корректно завершается и для проектов без тестов, тогда как цель make test у них просто отсутствует; checkout выполняется с fetch-depth: 0, иначе diff для поиска затронутых папок невозможен.
